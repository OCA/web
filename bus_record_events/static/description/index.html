Bus Record Events

Refreshes open views when their records change on the server.

When a record is created, written or deleted, the server sends one bus notification per model per transaction. The notification contains record ids only, never field values. Open form, list, kanban, calendar, pivot and graph views of that model reload by themselves.

The module patches the standard view controllers, so views with a custom js_class refresh too.

Configuration

A model broadcasts its changes when all of these are true:

  • A window action opens it. A model with no action can have no open view.
  • It is not transient, abstract or an SQL view (_auto = False).
  • It is not on the built-in denylist (ir.*, mail.*, bus.*, queue.job*, calendar.attendee and other high-churn technical models).
  • It is not on the configured denylist.

Set these system parameters in Settings > Technical > System Parameters:

Parameter Value Effect
bus_record_events.denied_models Comma-separated model names or patterns, such as hr.employee.location.history, x_* These models never broadcast.
bus_record_events.allowed_models Comma-separated model names or patterns Overrides the built-in denylist for these models.
bus_record_events.ignored_fields JSON, such as {"project.task": ["x_gps_lat", "x_gps_lng"]} A write that changes only these fields does not broadcast.
bus_record_events.retention_minutes Integer, default 15 Record events older than this are deleted.

Code can decide for a model, without configuration:

class EmployeeLocation(models.Model):
    _inherit = "hr.employee.location.history"
    _bus_record_events = False  # never broadcast; True: always broadcast


class ProjectTask(models.Model):
    _inherit = "project.task"
    _bus_record_events_ignored_fields = ("last_sync_hash",)

Setting these attributes needs no dependency on this module. When several modules inherit the same model, the ignored fields of all of them apply.

To stop events for one operation, such as a large import, add bus_record_events_disable=True to the context.

Usage

Open the same list in two browsers. Change a record in one browser. The other browser reloads the list within a few seconds.

How each view reacts:

  • Form: reloads only when its own record changes. If the user has unsaved changes, the form shows a warning and reloads after the user saves or discards. If the record is deleted, the form goes back to the previous view.
  • List and kanban: reload at most once every 5 seconds. They wait while the user edits a row, has records selected, uses kanban quick create or drags a card.
  • Calendar: reloads at most once every 5 seconds.
  • Pivot and graph: reload at most once every 30 seconds.
  • A view in a hidden browser tab does not reload. It reloads when the tab becomes visible again.

Use the hook in a custom component:

import {useRecordStream} from "@bus_record_events/hooks/use_record_stream.esm";

useRecordStream("res.partner", {
    onReload: () => this.load(),
    isBusy: async () => this.state.editing,
});

Known issues / Roadmap

  • Only changes made through the ORM create, write and unlink methods broadcast. Stored computed fields, raw SQL and database cascades do not.
  • An SQL view model (_auto = False), such as most reporting models, never broadcasts. Pivot and graph views on these models do not refresh.
  • A form does not refresh when only its one2many lines change.
  • The model channel is checked against access rights, not record rules. An internal user who can read a model receives the ids of every changed record of it, including records that record rules hide. Field values are never sent.
  • Events missed while the browser is disconnected for longer than the retention period are lost. The views do not reload on reconnection.
