Web Responsive App Grid

This module turns the web_responsive app drawer into a phone-like home screen.

App icons live on a free-form grid (6 columns, 4 on narrow screens) and can be arranged anywhere, just like on an iPhone or Android home screen. Icons can be grouped into sections separated by horizontal rules with optional titles.

The arrangement is stored per user, so every user can organize their own home screen, and it survives resizes: positions are kept per row and column, so shrinking the window only wraps the rightmost icons onto an extra row inside their group.

Important

This is an alpha version, the data model and design can change at any time without warning. Only for development or testing purpose, do not use in production. More details on development status

Configuration

No server-side configuration is needed.

Each user’s layout is stored in their user settings. From the app’s More / Options link (edit mode), the App Menu Preferences dialog offers a Reset layout button that clears the arrangement and rebuilds the grid in the default menu order.

While this module is installed, the web_responsive tint/preferences systray icon is hidden (the same preferences open from the grid’s Options link).

Usage

Open the app drawer (the grid button in the navbar, or the Home key).

  • Click an app to open it.
  • Long-press anywhere on the grid (~0.5s) to enter edit mode — or press and hold an icon and start dragging in the same gesture.
  • Drag an icon onto an empty cell to move it. Drag onto another icon — the apps shift right (wrapping to the next row) to open the slot, and a faded copy of the dragged icon shows where it will land.
  • Drop near a row’s top or bottom edge — a dashed horizontal line shows where a group boundary will be created. Drop on an icon’s left/right edge to split a group at that point.
  • Groups show a horizontal separator. Double-click it to type a name; the × removes the boundary. Drag the separator itself to reorder groups.
  • Save exits edit mode and persists; Discard undoes the last change (multiple steps); + Group adds an empty group; Options opens the per-user App Menu Preferences, including a Reset layout button that restores the default order. Escape also exits edit mode.

Design record

  • Separate addon on 19.0, template patch replacing .o-app-menu-list inside web_responsive.AppsMenu — keeps review blast radius small.
  • Row-semantic layout rows: [{cells: {col: menuId}, title, sep}] persisted per user in res.users.settings.apps_menu_grid_layout ({v: 2, rows}, v1 migrates): positions survive resizes.
  • Separators are explicit (sep flag) overlays on a margin — never grid rows.
  • makeDraggableHook (PoS floor-plan mechanism); drop targets resolved by cached cell rects + scroll delta, not elementFromPoint.
  • Alternatives rejected: editing web_responsive in place, stacking on PR #3756, useSortable, auto-fill columns, swap-on-drop (superseded by insert-shift), flat cell indexes (superseded by row-semantic).
